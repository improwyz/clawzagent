# ADR 0005 — v1.1 verification gates & supply-chain audit

- **Status:** Accepted
- **Date:** 2026-05-31
- **Release:** 1.1.0

## Context

For the 1.1.0 release the full audit/refactor program was verified end-to-end,
including the database-backed features (distributed rate counters, idempotency)
against a live Postgres and the supply-chain tooling that earlier ADRs had
deferred for lack of tools. The tools (Postgres, cargo-audit, cargo-deny,
cargo-udeps) were provisioned in ephemeral Docker containers and removed after.

## Verification gates

- `cargo fmt --check` — clean.
- `cargo build --workspace` (default features) — green.
- `cargo test --workspace` — green in isolation (incl. the live-DB tests when
  `DATABASE_URL` is set). Note: a single worker test that drives the Docker
  daemon (`orchestration::bollard_scheduler`) can flake under heavy *concurrent*
  load when other containers are competing for the daemon; it passes 630/630 run
  on its own. Not a regression.
- **Clippy gate (corrected):** `cargo clippy --workspace --all-targets -- -D
  warnings` (default features) — clean.

### `--all-features` is not a valid whole-workspace gate

`cargo clippy/build --all-features` across the whole workspace **cannot** pass,
by design:

- `clawz-platform` defined `detect_platform_auto` once per tier feature
  (`t0..t3`); `--all-features` enabled all four → duplicate definitions. **Fixed**
  in 1.1 by selecting exactly one definition via priority `cfg`s + a no-tier
  fallback.
- `clawz-embedded` is a `no_std` embedded crate; its features pull in
  `embassy`/`#![feature(...)]`/`no_std` paths that are fundamentally
  incompatible with a host `std` build. Enabling them together cannot compile.
  This is inherent to embedded crates, **not a defect** — the embedded crate is
  built for its target with its own feature set. The whole-workspace gate
  therefore uses default features (which build every crate, embedded included).

## Supply-chain (cargo-audit / cargo-deny)

- **`cargo audit`:** one advisory — **RUSTSEC-2026-0002**, an *unsoundness*
  (`IterMut` violates Stacked Borrows) in `lru 0.12.5`, pulled transitively via
  `ratatui 0.29 → clawz-tui`. **No semver-compatible fix exists:** `ratatui 0.29`
  pins `lru` to `0.12.5`, and `cargo update`/`--precise` cannot move it. Resolving
  it requires a `ratatui` major bump, which risks TUI API breakage for an
  unsoundness (not a remote-exploitable vulnerability) in a transitive UI
  dependency. **Accepted, with remediation path:** bump `ratatui` (and adapt
  `clawz-tui`) when a release using a patched `lru` is available.
- The other ~20 audit entries are `unmaintained` warnings for gtk-rs/webkit/wry
  bindings reached through the Tauri desktop stack — not fixable without upstream
  Tauri changes; informational.
- **`cargo deny`:** `bans` clean (no problematic duplicate versions). `advisories`
  and `licenses` "fail" only because the repo has **no `deny.toml` policy** — the
  license result is deny's strict default allowlist, not a real violation.
  Defining a project license policy (`deny.toml`) is a governance decision left
  to the maintainers and is out of scope for this release.

### cargo-udeps (unused dependencies) — blocked in this environment

`cargo-udeps` could not run here due to a toolchain pincer: the **latest**
cargo-udeps requires `rustc ≥ 1.93` to compile (its `cargo-*` deps do), while an
**older** cargo-udeps links a `cargo` library too old to parse the workspace's
`edition2024` manifests (`clawz-gateway`/`worker`/`services`). The available
nightly image satisfies neither end. Unused-dependency analysis is therefore a
follow-up to run once a compatible toolchain is on hand; it is a cleanliness
check, not a security gate (cargo-audit/deny cover vulnerabilities).

## Tooling lifecycle

Postgres (`pgvector/pgvector:pg15`) ran in a throwaway container on an isolated
host port; cargo-audit/deny/udeps ran in ephemeral `--rm` Rust containers. All
were removed after verification, leaving no tooling installed on the host.
